# Baseline: Iris vs Pi on the full catalog

**Published:** 2026-11-20 (revision 2 — Iris shell allow mode)
**Model:** locally served `qwen3.6-35B-Q1` through an OpenAI-compatible endpoint
**Result:** Iris **14/17 (82.4%)**, Pi **13/17 (76.5%)**; one repetition per task.

This is Gauge's initial published baseline (plan phase 8 and v1 requirement 10).
Both agents ran the same suite, task revisions, fixtures, and independent
evaluators in the same session window. It is a single-run snapshot, not a
statistically significant comparison.

## Revision history

The first version of this report used an Iris configuration with
`[security.shell] mode = "allowlist"` and a narrow command list. That policy
artificially limited Iris (44 shell-policy denials; 10/17 with 3 timeouts) and
was superseded. This revision uses `mode = "allow"` with
`[security] external_sandbox = true`, and both agents were rerun in the same
window. The earlier experiments (`full-iris-20261120T093529Z-40c36d` and
`full-pi-20261120T100950Z-b7480a`) remain in the local store for audit.

## Observations

- Correcting the Iris shell policy removed the artificial capability limit:
  the paired run has zero timeouts, 55 failed tool calls instead of 140, and
  Iris improved from 10/17 to 14/17 versus the superseded allowlist run. Shell
  denials disappeared; the remaining failures are model/tool-interface issues
  (29 malformed edit calls missing `path`, 25 reads against wrong or
  non-existent paths).
- The policy change affected more than denials: compared with the allowlist run,
  Iris additionally passed `text-snake-case`, `text-title-case`,
  `text-join-nonempty`, `notes-cli-tag-filter`, and `notes-json-persistence`, but
  `notes-search` regressed from pass to fail. Single-run outcomes should not be
  attributed to the policy alone.
- Pi's own run-to-run variance is visible: the earlier Pi run passed 14/17 with
  `greeting-all`, `notes-json-persistence`, and `text-snake-case` failing; the
  paired rerun passed 13/17 with `text-wordcount`, `text-dedupe`,
  `text-join-nonempty`, and `notes-cli-tag-filter` failing. One repetition is
  not enough to rank these agents.
- Iris used slightly fewer LLM requests (203 vs 208) but far more input tokens
  because it does not report prompt-cache reuse. Pi was much faster (median 50s
  vs 1m56). Output tokens were similar (46k vs 34k).
- Both agents pass every operational task. `text-dedupe` is the only task both
  fail in this paired run.
- The remaining tool failures are malformed edits and path mistakes, not
  evaluator or Gauge errors: both agents had zero evaluator errors, zero
  not-evaluated attempts, and zero setup/execution failures.

## Reproduction

Start a local OpenAI-compatible endpoint serving the model, write the
configuration shown above (including the allow-mode Iris settings), then:

```bash
gauge --config baseline.toml run --suite full --agent iris --notes "baseline"
gauge --config baseline.toml run --suite full --agent pi --notes "baseline"
gauge --config baseline.toml compare <iris-experiment> <pi-experiment> --format markdown
```

Gauge pins the suite, task content fingerprints, fixture revisions, agent
configuration hashes, and environment in the experiment record. Compare refuses
mismatched task selections.

## Limitations

- **One repetition per task.** No confidence intervals or statistical
  significance. Pi alone moved by one task between two runs, and several
  per-task outcomes flipped; treat small differences as noise.
- **Local, unpinned server.** The endpoint's llama.cpp/llama-swap build,
  quantization, sampling configuration, and host load are not recorded beyond the
  server-reported model name and the context configured here.
- **External sandbox acknowledgment is not a sandbox.** `external_sandbox = true`
  was set to enable Iris `allow` mode because the tasks are trusted. Local Gauge
  execution remains unisolated; do not run untrusted tasks this way.
- **Different telemetry.** Iris does not expose a version or cached-token
  counts; Pi's total includes prompt cache. Tool-failure counts reflect each
  agent's tool surface and policy.
- **Settings content is not in the adapter config fingerprint.** Gauge's
  experiment-level config fingerprint covers the settings-file path, not its
  bytes; the settings hash is recorded per attempt (and in this report). A
  `gauge compare` between runs with different settings would not flag the
  settings change.
- **Go-only catalog, local backend.** The catalog has 17 Go tasks; execution is
  not sandboxed. Docker isolation is the remaining phase.
