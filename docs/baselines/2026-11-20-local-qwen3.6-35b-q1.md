# Baseline: Iris vs Pi on the full catalog

**Published:** 2026-11-20
**Model:** locally served `qwen3.6-35B-Q1` through an OpenAI-compatible endpoint
**Result:** Iris **10/17 (58.8%)**, Pi **14/17 (82.4%)**; one repetition per task.

This is Gauge's initial published baseline (plan phase 8 and v1 requirement 10).
Both agents ran the same suite, task revisions, fixtures, and independent
evaluators. It is a single-run snapshot, not a statistically significant
comparison.

## Observations

- Pi passed four tasks Iris did not: `text-dedupe`, `text-title-case`,
  `text-join-nonempty`, and `notes-cli-tag-filter`. Iris additionally timed out
  on `notes-json-persistence`; Pi reached the evaluator there but failed it.
- Both agents failed `greeting-all` in different ways: Iris changed or broke
  existing `Greet` behavior and returned the wrong `GreetAll` results, while Pi
  preserved `Greet` and passed the ordering check but failed the empty-slice
  (non-nil) check.
- Both agents failed `notes-json-persistence`; neither produced working
  persistence in this run.
- `text-snake-case` timed out for both agents at the 5-minute attempt limit.
  This is a candidate for task review (prompt precision or timeout), not
  evidence about one agent.
- Iris's failed tool calls were dominated by 67 malformed edit calls (missing
  `path`), 44 shell commands denied by the configured allowlist, and reads
  against a non-existent `/workspace/...` path. Pi's 25 failed tools were mostly
  bash errors and malformed edit arguments. These are model/harness
  interactions, not Gauge evaluator failures; the narrow Iris shell allowlist is
  part of the measured configuration.
- Iris used fewer LLM requests (143 vs 200) but far more input tokens, since it
  does not report prompt-cache reuse. Pi was faster overall (median 52s vs 1m13).
- The agents ran sequentially (Iris first). Local prompt caching, machine load,
  and model nondeterminism can affect a single run; see limitations.

## Reproduction

Start a local OpenAI-compatible endpoint serving the model, write the
configuration shown above, then:

```bash
gauge --config baseline.toml run --suite full --agent iris --notes "baseline"
gauge --config baseline.toml run --suite full --agent pi --notes "baseline"
gauge --config baseline.toml compare <iris-experiment> <pi-experiment> --format markdown
```

Gauge pins the suite, task content fingerprints, fixture revisions, agent
configuration hashes, and environment in the experiment record. Compare refuses
mismatched task selections.

## Limitations

- **One repetition per task.** No confidence intervals or statistical
  significance; a single task outcome can flip between runs.
- **Local, unpinned server.** The endpoint's llama.cpp/llama-swap build,
  quantization, sampling configuration, and host load are not recorded beyond the
  server-reported model name and the context configured here.
- **Different telemetry.** Iris does not expose a version or cached-token
  counts; Pi's total includes prompt cache. Tool-failure counts reflect each
  agent's tool surface and policy.
- **Configured shell policy.** Iris ran with a narrow shell allowlist; a
  different policy (or approval mode) may change its behavior.
- **Go-only catalog, local backend.** The catalog has 17 Go tasks; execution is
  not sandboxed. Docker isolation is the remaining phase.
